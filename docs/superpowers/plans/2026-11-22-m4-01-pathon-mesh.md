# M4-01: `pathon-mesh` — plan wdrożenia

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Cel:** wiele meshy w jednej puli mega-buforów (alokacja, odroczone zwalnianie, reuse, diagnostyka wyczerpania), layouty wierzchołków mapowane na `pathon-rhi-types`, dane poprzedniej klatki dla wektorów ruchu (transformacje, układ pozycji skinowanych dla M4-12); wspólne dla forward, visibility buffer i RT.

**Spec:** [ADR-0027](../../adr/0027-pula-geometrii-i-dane-poprzedniej-klatki.md), [ADR-0020](../../adr/0020-kontrakty-rhi-types.md) (polityka rozrostu), [ADR-0022](../../adr/0022-zegar-klatki-paczek.md) (zegar klatek); M4-01 w [planie](../../plan-implementacji.md).

## Ograniczenia globalne

- Zwykła paczka: zależy tylko od `pathon-api` (xtask `pack-boundary` z `kind = "pack"`), poza domknięciem rdzenia; brak wgpu.
- Nowe publiczne struktury: `#[non_exhaustive]` + konstruktory (ADR-0020). Błędy z kodem `M…` i podpowiedzią.
- Kod samokomentujący, docs po polsku; wasm check przechodzi.

## Review Focus

1. Alokacje różnych meshy nigdy się nie nakładają (wierzchołki i indeksy), także po zwolnieniu i reuse; dane wracają z GPU tam, gdzie pula twierdzi, że leżą.
2. Zwolnienie jest odroczone o `frames_in_flight`: zakres nie wraca do alokatora wcześniej, uchwyt jest martwy od razu, stary uchwyt nie trafia w reuse slotu.
3. Granice: mesh dokładnie równy chunkowi, o jeden większy (chunk dedykowany), większy niż limit (`M0005`), pusty, indeks poza zakresem, budżet wyczerpany (`M0003`) a fragmentacja (`M0004`); nieudany upload zostawia pulę bez wycieku zakresów i chunków.
4. `TransformHistory`: `previous_model` to `model` z poprzedniej klatki, nowy obiekt nie ma ruchu, `begin_frame` idempotentne.
5. Test GPU: ≥3 różne meshy z jednego mega-bufora (z niezerowym `base_vertex`), odczyt pikseli; reuse po usunięciu.
