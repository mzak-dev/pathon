# M2-12: `pathon-profile` — plan wdrożenia

**Cel:** passy grafu mają nazwane spany CPU i czasy GPU (timestampy) widoczne w `tracing`, Tracy i puffin, bez zależności rdzenia od profilu i z zerowym kosztem, gdy obserwator nie jest ustawiony.

**Spec:** [ADR-0026](../../adr/0026-profilowanie-passow.md), [ADR-0007](../../adr/0007-logowanie.md), [ADR-0020](../../adr/0020-kontrakty-rhi-types.md).

## Ograniczenia globalne

- `pathon-core` nie zależy od `pathon-profile`; baza rdzenia (126 crate'ów) bez zmian; wasm check przechodzi (Tracy tylko natywnie).
- Feature'y `tracing`, `tracy`, `puffin` domyślnie wyłączone.
- Kod samokomentujący, docs po polsku.

## Review Focus

1. Nazwy spanów i timestampów to nazwy passów grafu (test na `rhi-null` i na GPU); pass z własnymi `timestamps` zostaje nietknięty.
2. Indeksy zapytań są poprawne (rhi-null je sprawdza), resolve obejmuje dokładnie użyte zapytania, pierścień slotów nie odczytuje slotu, którego klatka nie dotarła do GPU (`frame_abandoned`).
3. Zero kosztu: bez obserwatora lista komend jest identyczna jak dotąd; bez feature'ów brak zależności `tracing` / Tracy / puffin.
4. Błędne/graniczne wejścia: urządzenie bez `TIMESTAMP_QUERY`, wasm, więcej passów niż pojemność, utrata urządzenia.
